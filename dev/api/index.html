API

The exported macros @↓ and @↑ are the public API. The internal helpers are listed for reference and may change without notice.

ArrowMacros.ArrowMacros — Module

ArrowMacros provides @↓ ("download": unpack struct fields into locals) and @↑ ("upload": write locals back into struct fields) — the syntactic spine of the NSDE packages. Field access goes through Val-specialized getproperty/setproperty!, so the sugar costs nothing at run time.

ArrowMacros._entries — Method
_entries(ex, form)

internal: the entries of a macro's field list ex — a single entry or a tuple of them. Every entry must be a bare name or an arrow name ← value; anything else raises an error naming the expected form, rather than being silently dropped.

ArrowMacros._get — Method

internal: getproperty with the field name lifted into a Val, so the lookup specializes at compile time and the macro sugar costs nothing at run time.

ArrowMacros._prepend! — Method
_prepend!(ex, s; indexing=false)

internal: rewrite bare symbols inside the arrow expression ex into field lookups on s, in place. indexing records whether ex sits inside an indexing expression. The rules, pinned by the test suite because the NSDE packages rely on them:

  • Bare symbols become field lookups; literals stay as they are.
  • Constants nothing, missing, π, ℯ, im, Inf, NaN are left alone.
  • Inside indexing expressions, begin and end keep their Julia meaning.
  • The head position of calls, macro calls and dotted names is left alone: f(a) keeps f, Base.abs(a) keeps Base.abs.
  • In chained comparisons (0 < a < 2) only the operands are rewritten.
  • Keyword names are left alone: round(a; digits=2) rewrites a only.
  • Dotted access is not rewritten: in a.c, a stays a local name. Bind the field first (@↓ tmp ← a = s) if you need s.a.c. This is what protects qualified names, at the price of chained access.
  • Indices follow the symbol rule: in b[i], i must be a literal or a field.
  • Names bound inside the expression, such as anonymous-function arguments and comprehension variables, are rewritten too, so such expressions are not supported.

ArrowMacros.@↑ — Macro
@↑ s = a, b ← f(c)

"upload": write local values into fields of s. @↑ s = a, b sets s.a = a and s.b = b; the arrow form sets a field from any expression: @↑ s = a ← 2b sets s.a = 2b with b a local variable. Unlike @↓, the right of ← here is plain code, not field-rewritten. Writing to a name that is not a field of s throws the usual field error.

source
ArrowMacros.@↓ — Macro
@↓ a, b ← f(c) = s

"download": unpack fields of s into local variables. @↓ a, b = s binds a = s.a and b = s.b. The arrow renames or transforms: @↓ x ← b = s binds x = s.b, and the right of ← may be an expression in which bare symbols read as fields of s: @↓ x ← 2a + b[1] = s binds x = 2s.a + s.b[1].

In the expression form, function names, macro names, qualified names (Base.abs) and keyword names are left alone, and so are literals, the constants nothing, missing, π, ℯ, im, Inf, NaN, and begin/end inside indexing. Other bare symbols are fields of s. Chained access a.c is not rewritten: bind the field first. A name that is not a field of s throws the usual field error.
